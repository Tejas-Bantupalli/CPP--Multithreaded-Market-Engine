Market Engine Anatomy

How a strategy thread's decision becomes a resting order, a fill, and an event that every other agent reacts to. Five figures, read top to bottom.

1. Threads and queues

A run has three kinds of thread. One engine thread owns the order book and every agent's cash and position, and is the only thread that ever touches them. One thread per agent runs your strategy. One logger thread writes files. Every pair that talks does so through a single-producer single-consumer ring buffer, so there is no mutex anywhere on the trading path.

2. Life of an order

Follow one market-maker quote from decision to fill. Each hop is one function; the numbers match the sequence below the figure. The right-hand column shows which latency histogram covers which span.

  1. Strategy decides. Inside on_event or on_idle it calls ctx.submit(side, px, qty, tif). Prices are integer ticks: 9998 is $99.98.
  2. AgentContext builds a Command. Order id is (agent_id << 40) | local_seq. It stamps t_submit and pushes. Nothing blocks; a full queue is counted and the call returns 0.
  3. Engine drains. Each pass visits every agent's queue, pops up to 256, and records now − t_submit into that agent's submit_to_pop histogram.
  4. Batch sorted by submit time. Whoever submitted first is processed first, regardless of which queue was visited first. No shared counter needed.
  5. Book matches. OrderBook::add walks the opposing side while the order still crosses (Figure 3). It knows nothing about threads or time.
  6. Results come back as data. A list of fills, a list of same-agent resting orders that were cancelled, and whether anything rested.
  7. Engine updates portfolios. Buyer cash down and position up; seller the reverse. This copy is the one the final PnL table uses.
  8. Engine publishes events. An Ack to the submitter, a Fill to each side of every trade, a Trade to everyone. After the whole batch, a BookUpdate to everyone if the top of book changed.
  9. Agent pops and dispatches. AgentContext::dispatch records delivery latency, updates the agent's own position, cash, and top-of-book view from the event, then calls the strategy.
  10. Strategy reacts. on_event runs with the fresh context. The time from step 9 to the next step 2 is the react histogram, your strategy's compute cost.

3. Inside the book

The book is a flat array with one slot per price tick across the configured band, so finding a level is array indexing. Each level is a doubly linked FIFO of order nodes drawn from a pool. Orders are addressed by pool index, so the pool can grow without invalidating anything.

What goes in

struct Command {
  CmdKind kind;      // New | Cancel
  Side side;         // Buy | Sell
  TimeInForce tif;   // GTC | IOC
  AgentId agent;
  OrderId id;
  Price px;          // ticks
  Qty qty;
  Ts t_decide;       // event it reacted to, or 0
  Ts t_submit;
};

What comes out

struct Fill {
  OrderId maker_id; AgentId maker;
  OrderId taker_id; AgentId taker;
  Side taker_side;
  Price px;          // maker's price
  Qty qty;
  Qty maker_remaining;
};
struct AddResult {
  bool accepted; RejectReason reason;
  Qty filled; Qty resting;
};

4. Events: who hears what

One fill fans out to four events. Private events go only to the agent that owns the order; broadcasts go to every inbound queue. An agent that has fallen behind loses events rather than stalling the engine, and the loss is counted per agent.

Position and cash therefore exist twice on purpose. The engine's copy is authoritative and produces the PnL table. The agent's copy inside AgentContext is rebuilt from its own Fill events, so a strategy can manage inventory without reading any shared state. The tests assert the two agree whenever no events were dropped.

5. Latency hops

Five histograms, each with exactly one writing thread and read only after that thread is joined. Recording is a few integer operations and no atomics.

6. Shutdown, in order

The order matters because the engine must process every order that was ever submitted, and a producer must never push after the engine has decided it is finished.
